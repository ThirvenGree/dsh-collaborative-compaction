# DSH 多模型协作压缩

新插件提供模型处理与设置页；billion-context 仍是唯一压缩范围、历史保留和提交者。主会话继续使用它原来的 DeepSeek 模型。

- A：通过 DSH 的 LLM 服务，使用可配置 Provider / Model 和 billion-context 的压缩指令生成候选。默认 `deepseek-account/deepseek-flash`，复用本机 DSH 账户，不另存密钥。
- B：Claude Messages 的原生按需压缩 `compaction: {type: "summarize"}`，beta `compact-2026-09-04`，默认 `claude-sonnet-5-5`。不把普通聊天摘要冒充原生压缩。
- 审核：`gpt-6.1-terra` Responses API，同时读取本次原始历史、A、B。`store:false`，推理强度可调。
- 关闭交叉审核时只运行所选摘要源：Claude 开启为 B，否则为 A；交叉审核开启时为 A+审核或 A+B+审核。独立事实核验可单独开关，任一启用阶段失败均不提交。
- Key 从 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` 读取；Windows User/Machine 环境变量异步读取并缓存。不写入源码、运行记录或设置页。

## 引擎适配

基于 billion-context v0.1.212 的本地分支。 保留上游 0.1.212 的时间戳、schema v10、只读存储快照与消息水位优化，同时迁移本机原文 FTS、多模型事务、90% 硬阈值和后台追加兼容。不会用上游较窄的摘要搜索覆盖原文检索。复用 `compress.externalSummary` 和 `providers`，不新增第二套调度器。插件启动时在 IPv4 loopback 建立带随机令牌的本地摘要服务；引擎私有凭据库只保存本地服务令牌。

`compress`、后台预先折叠和 `/compact` 共用引擎范围与校验。候选生成期间只隔离压缩相关字段；草稿不进入持久化队列，提交按字段增量合并，保留懒加载 Map 和无关状态。整批通过才提交，版本冲突放弃。严格模式禁用紧急 CPU 摘要、摘要截短补救、近期保留区放宽；无法安全压缩时明确失败，不牺牲已保护历史。跨多轮压缩读取缓存原文；原文缺失时拒绝只对旧摘要进行审核。

原始会话和恢复材料继续由 DSH 与 billion-context 保存。模型处理不写入角色、人设或记忆插件。正常配置关闭或插件停用恢复之前的压缩配置。异常进程退出时旧本地端点可能不可达，此时压缩失败；重新启动 DSH 重建端点即可。

## 设置与观察

DSH 设置 → 多模型协作压缩。可配置开关、模型、环境变量名、推理强度、超时重试、摘要预算、近期保留 token 和自动折叠目标。默认由模型决定何时压缩以及范围，自动折叠目标仅在关闭模型规划时供原流程使用。请求容量预检采用 tokenizer 加余量的估算；超过预算拒绝，需缩小范围。

每次运行显示 A/B/审核阶段、模型、耗时、usage 和错误，不记录密钥或聊天正文。`validated` 只代表候选校验成功，不代表已提交；最终提交见 billion-context 的压缩回执和会话块。费用不估算，Claude usage 使用 `usage.iterations`，避免误记为 0。

本地适配通过 `link:` 安装，避免市场更新覆盖修改。更新 billion-context 前须重放本地补丁、构建并回归测试；保留安装前备份，不宣称对未知新版本自动兼容。

## 安装（Windows / PowerShell 7）

本插件使用 [billion-context](https://github.com/ranxianglei/billion-context) 及其 [acp-kernel](https://github.com/ranxianglei/acp-kernel)。适配基于 v0.1.212，提交 daa082ead8a8ead60311e29ad4627bff0f569fc1；补丁与上游完整许可位于 patches/，并非上游官方发行版。

需要支持内置 `node:sqlite` 与 FTS5 的 Node.js 22（已验证 `22.22.2`）、npm、Git、已安装的 DSH 和可调用相应模型的账户。准备脚本会实际检测 SQLite 能力。先关闭 DSH 再安装，安装完成后重新打开。克隆目录须长期保留，安装使用本地目录链接。

1. 克隆本仓库：

~~~powershell
git clone https://github.com/ThirvenGree/dsh-collaborative-compaction.git
cd dsh-collaborative-compaction
pwsh -File ./prepare-engine.ps1
pwsh -File ./install.ps1
~~~

2. 若已构建适配引擎，可给 install.ps1 传入 -EnginePath；自定义 DSH profile 用 -ProfilePath 指定。安装前自动备份原包和配置，不覆盖其他目标的现存链接。安装脚本不负责停止正在工作的 DSH。
3. 通过 Windows 环境变量设置 ANTHROPIC_API_KEY 和 OPENAI_API_KEY，勿提交到仓库。插件默认关闭，在 DSH 设置「多模型协作压缩」中开启，确认模型名称与账户权限。
4. 自动压缩继续由 billion-context 调度；在正常会话中可用 /compact 手动触发。受保护的近期历史不足以提供压缩范围时不会强行压缩。
5. 可运行 node live-test.mjs 测试正在运行的本地摘要服务；会调用真实账户并产生费用，只使用脚本内合成内容。

GitHub Release 提供插件安装包及引擎补丁；不会托管你的 DSH 会话、提供云端服务或携带密钥。仅安装插件压缩包不足以完成引擎适配，仍须执行上述准备与安装步骤。

## 0.2.0：模型规划与事务修正

- 正常请求有合法候选历史时，请规划模型（默认 Terra，可切换）决定现在压缩、暂不或不确定；手动 /compact 和 compress 也进入同一规划路径。规划读取候选范围、上下文容量、近期任务片段，不以固定 token 阈值替代模型选择。片段有截取标记；规划只是提案，保护区、工具配对、范围和历史版本由引擎最终核验。没有合法历史时不调用模型。
- 低于硬性安全阈值时，规划暂缓不压缩、规划失败保留原文。达到有效上下文预算（含上游输出预留）的 90% 时，系统覆盖暂缓、不确定和规划失败；优先执行模型选择的合法历史，不足时由原引擎继续选取候选，目标降到有效预算的 81%。预算估计含系统/工具开销、图片预留和现有估计校准。不会放宽近期保护、工具配对、原文保留或独立审核；若无法安全压缩，容量检查仍可阻止请求。调用量会高于仅阈值触发，设置页分别记录规划、摘要、交叉审核与事实核验。规划记录 decided、摘要 validated 都不等于引擎已提交。
- 新增独立事实核验：单独模型调用对照原文与最终摘要，并要求引用关键事实证据。代码验证证据原文和摘要引文确实存在；核验不通过或引文不匹配拒绝提交。该机制减少错误，不构成所有语义事实的数学证明。
- 引擎配置路径遵循 BILI_CONFIG_FILE > XDG_CONFIG_HOME > 默认目录；备份按实际路径分开。
- 安装脚本在失败后恢复包、链接、manifest 和锁文件。中断后保留事务记录，可用同一 ProfilePath 执行 install.ps1 -Rollback 恢复。

0.2.x 验证：插件单测 11/11；引擎事务与规划专项 17/17，既有外部摘要回归 23/23；手动路由专项通过，构建与类型检查通过。实际安装链路中模型选出两个范围，A、B、交叉审核、独立事实核验全部成功，提交后原文保留且持久化重载恢复。安装回滚在创建链接后和修改 manifest 后分别注入失败，均恢复原状态。较广 DSH native 运行时恢复用例仍存在事件循环提前退出问题，未宣称全库通过。


## 0.3.0 审查修复
- 本地请求按字节累计，最大 9,000,000 bytes；完整拼接后严格 UTF-8 解码。非法编码拒绝，不替换成乱码。
- 自动规划对相同 ref/token 候选复用 wait/uncertain，最长 30 分钟；候选或配置变化会重判。引擎保留自动退避。插件只对内容校验明确拒绝的请求冷却 10 分钟；HTTP 429、5xx、网络异常和超时不建立插件冷却。达到 90% 时，引擎通过 pressure=hard 标记请求，允许越过冷却，但相同输入正在执行时仍然去重。事务副本仅在确定执行后创建。硬阈值下模型范围被拒后转由引擎候选处理。
- 只有引擎当前由本插件接管时才恢复配置。每次关闭后重新开启，重新保存接管前快照。
- 默认规划 30 秒、低推理、2048 输出 token；全流程 540 秒。A、Claude、审核、核验分别配置输出预算（默认 16384 / 24576 / 49152 / 16384）。旧设置保留，升级本机设置时可显式迁移。
- 默认事实核验改用 Claude Sonnet，与 Terra 审核分开；可配置 claude/openai。检查整份摘要，但最多引用 24 条关键事实，并对数字、路径及技术标识符做确定性原文匹配。它是有边界的核验，不证明没有任何遗漏。合法的数字改写可能被严格检查拒绝，提示词要求保持原格式。
- 输入预算使用 o200k_base tokenizer 加 25% 余量的估算，不再把每个 UTF-8 字节当作一个 token。该编码不是所有配置模型的原生 tokenizer，服务端容量检查仍是最终边界，超限不提交。
- 摘要长度通过版本化 metadata.dsh_compaction 传递；缺少结构化预算直接报错，不依赖自然语言提示词正则。
- 网络失败、429/5xx 均带可取消的指数退避，遵守 Retry-After，由本次调用的总时限负责取消。运行记录保留最近 500 个已完成记录，读取最多 100 个；正在运行的记录不删除。
- 从源码安装前先执行 `npm ci --ignore-scripts`，再准备引擎并运行安装脚本。

0.3.0 验证：插件 20 项、引擎定向回归 43 项、手动命令 1 项通过，类型检查和构建通过。68 万字中文分块解码与 12000 字摘要预算测试为本地回归；真实 Claude 核验成功。真实 A/B 成功，Terra 审核仍返回 429，因此本次完整链路未通过，失败不提交。


## 0.3.1 运行路径修复
- 暂缓缓存不再包含 revisionEpoch。新候选覆盖旧候选且相对原判断的累计 token 增长不超过 min(8000, 窗口10%) 时沿用；不滚动重置基线或30分钟有效期。候选收缩、缺失、配置变化或硬阈值均不复用。
- prepare 后 epoch 改变仍能命中；有真实 OpenAI prepare → preflight 连续请求回归。规划前不再全量序列化 state/history，而在会话锁内核对 epoch 与对象引用；真正提交时仍使用完整事务冲突校验。
- 列表行首序号先剥离（不会误删小数），单个无单位整数与最多3字母全大写缩写仅记录 softLiteralWarnings，不据此拒绝；日期、带单位数字、多位数字、小数、路径及技术标识符继续校验。
- 明显装得下的输入按 UTF-8 字节上界直接通过，完全不分词。需要精算时在 worker_threads 中运行 o200k_base；单次流水线按组成部分缓存计数，原文供 B、审核和核验复用。工作线程退出/异常拒绝预算检查；取消请求可退出等待。
- 分词仍有CPU耗时，并不是零耗时；目的为避免阻塞宿主事件循环。每次流水线结束后原文计数缓存随调用释放，不建立全局聊天原文缓存。
- 0.2.x 保存过的配置不会自动覆盖用户值；本机确认 timeoutMs 已为 540000，规划为 30000。

## 0.3.3 恢复与多 profile

Windows 使用命名管道，Linux 使用抽象 Unix 套接字，macOS 使用绑定到本机回环地址的端口锁。宿主异常退出后，内核会释放锁。若锁正在使用，配置保持原样。
启动优先使用明确的 profile，旧启动器未提供路径时采用最后一次安装登记。旧版共享目录中的令牌、设置和引擎备份只复制给登记的原 profile，已有目标文件优先。重新启用或关闭前会检查旧端点。端口仍可连接、超时或无法核实时保留原配置；确认端口拒绝连接后，使用原备份恢复或接管。
只有桌面命令处理器能把压缩标为手动重试。模型生成的工具参数不能改变触发来源。

## 检索原文与后台压缩

在当前会话中，`search_context` 同时查找原始消息、压缩块和可用的附件文字说明。输入 `block:b1 关键词` 可限定一个块；把命中项的 `open:ev-…:偏移` 原样交给同一个工具，可以继续读原文。相邻消息帮助理解语境，只有明确记录的更正才标为更正。旧块如只剩扁平文本，结果会标明无法核对说话者或时间。跨会话也使用本机全文索引：传入 `conversation_id` 指定已知的引擎会话 ID 或唯一的标准会话 ID，搜索磁盘上的原始记录及目标会话已经送达引擎、尚未落盘的新消息。结果明确标注来源会话；继续阅读时保持相同 `conversation_id`，把 `open:ev-…:偏移` 作为 `query` 传回。不会切换当前会话、解压目标历史或修改其会话状态；当前会话的 `acp_retrieve`/解压不能代替这种跨会话读取。未经过本引擎的 DSH 历史不能凭空检索，已删除内容及过期证据入口不会被恢复。

0.3.6 的正式工具路径使用后台 SQLite 全文检索。三字符以上使用 trigram，一至两字符使用独立字符片段索引，保留两字人名、参数内部片段、路径和标点的字面匹配。索引按实际记录变化增量维护，不再为每次查询读取整个持久化会话；本轮尚未落盘的新消息合并参与检索，同 ID 的新内容覆盖旧内容。

索引位于原数据库旁的 `index.db.search.sqlite`，可以重建，正式历史不被替换。搜索线程只读源库，独立索引使用回滚日志。首建和增量同步每批最多处理 250 条，索引行与游标一起真正提交；工作线程被终止后保留已经提交的进度，下次从游标继续，并补齐期间发生的更正、删除和新消息。同一批源修订影响多条消息时，以修订号和消息序号共同保存进度，不跳过同修订的剩余条目。未同步完整的索引不冒充完整搜索结果。

搜索采用 **120 秒无进展超时**，不是整次查询最多运行 120 秒。只有当前请求新增的已提交进度会延长等待；重复心跳、旧请求进度不能延长。共用工作线程的排队请求从轮到自己时开始计时。索引与查询在工作线程运行，只把命中片段、相邻消息和来源信息返回宿主。正常已保存结构化原文的块不会再加载整块懒加载文本；缺少结构化原文的旧格式归档仍保留兼容扫描，其首次文件读取可能有额外开销。工作线程不可用时明确说明搜索未完成，不把故障当成“没有这段历史”。

旧的版本缓存和同步读取接口保留用于兼容及对照测试。全文索引会增加磁盘占用与首次构建时间，不等于语义检索。实现依据、权限边界见 [全文检索设计](docs/history-search-design.md)，长历史数据与复测命令见 [对照报告](docs/history-search-benchmark.md)。

普通压力下，模型在后台选择范围并审核摘要；同一会话同时最多处理一笔。下一次请求抵达时，引擎重新核对选中消息、块依赖和工具边界后才提交。只追加到尾部的消息可保留。手动压缩和硬阈值继续走受保护的同步路径。进程重启会丢弃尚未提交的后台草稿，仍可用保留的历史重新处理。

此处的按需阅读借鉴了 [LCM](https://papers.voltropy.com/LCM) 的原文引用，以及 [DSH 分页历史检索](https://github.com/overact/dsh-context-management) 的检索方式。后台提交采用历史前缀验证，参考 [Claude 后台压缩](https://platform.claude.com/docs/en/build-with-claude/compaction-background)。不同宿主和模型的压缩率需以实际请求测量。
### 三路只读回放

在协作压缩设置页展开“三路回放”，或在本机运行 `node replay-live.mjs`。固定合成样例覆盖遗漏的工具名、后续更正、只提交一次但尚无成功回执，以及摘要已经足够的正对照。模型分别收到完整原文、摘要、可自主使用 `search_context` 的摘要。三路使用同一配置的 DSH 模型，任务、回答格式和评分条件相同。检索复用固定引擎的关键词定位和展开接口，只读取这一条样例。工具请求只作为测试选项，不会执行浏览器点击、发送、文件写入等动作。

程序分别检查答案和证据。引文必须能够回到指定记录，同时确实在该路提供的内容中出现。同文的其他记录不能替它背书。模型可以回答“不确定”。原文组本身未通过时，不能据此证明摘要丢失。调用失败与行为错误分别呈现。设置页仅读写合成套件的最新报告；刷新页面不会启动模型。回放对比借鉴 [ACON 的失败轨迹配对](https://arxiv.org/html/2510.00615v3)。固定样例用于诊断，不等价于正式对话中的成功率。

独处插件可以注入宿主服务 `censhuReplay.screenMethod({candidateId, method, probes}, {signal})`。调用方只提供已脱敏的候选方法、适用及例外两道问题和各自允许引用的真实回执摘录。候选方法文字不能充当其自己的原始证据。两种情境都必须有原文对照，并在允许回查的一路实际回查和给出可核对答案，才返回 `supported`。模型服务出错时返回 `unavailable` 和 `retryable`，余额或配置恢复后再试；这类失败不构成方法反例。方法回放不写入聊天和记忆，也不授权应用候选；独立审核、权限和采用条件仍由角色插件负责。需要重新比对时应以当前版本的原始回执为准。


### 回放怎样调整后续压缩

「回放验证后自动应用」开关保留为默认开启，协作压缩总开关仍默认关闭。两个开关均开启时，**首次基线由后台分批建立，无须先手动跑完整套校准**。初始化使用当前配置的真实压缩流水线生成摘要，再完成原文、摘要和可回查三路诊断；它只记录现行策略的表现，不会在小批样例通过后立即改写正式指令。只有发现可复现的遗漏，才进入提案和完整对照验证。如果关闭此开关，手动按钮只做三路诊断，不修改策略，也不启用后台校准。

每个成功步骤保存为检查点。达到单批调用或时间预算、每日预算不足，或宿主重启时，下一次后台机会会从保存的进度接着运行；正在执行但尚未保存结果的请求不能算完成。后台机会不依赖用户再发一条消息，普通聊天也不会逐条启动整套校准。模型、摘要作用范围、策略版本或本轮样例内容变化后，旧检查点不能冒充新范围的验证。用于检验重复性的第二次压缩使用独立任务编号，必须重新生成，不能拿第一次缓存的摘要再算一次。

基线建立以后，常规定期检查每七天最多完成一次，动态题库新增样例另有 24 小时窗口。预算暂停不等于失败，技术失败不等于完成；只有本轮得到完整结论才更新完成窗口，技术失败按退避规则再试。设置页区分初始化、运行、预算暂停、失败和完成，显示问题覆盖、当前阶段、暂停原因、下一次考虑时间及使用量。已有的技术标识、后续更正和执行回执三类策略继续兼容。

校准的运行预算可以在设置页调整：

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| `replaySliceCalls` | 12 次 | 每批可发起的模型请求数；A、B、审核、核验与网络重试分别计数 |
| `replaySliceMs` | 120,000 ms | 每批接纳新请求的时间窗口；不据此强行中断已经发起的调用 |
| `replayResumeMinutes` | 15 分钟 | 分批暂停后最早恢复间隔；每日预算用尽时等下一 UTC 日 |
| `replayDailyCalls` | 120 次 | 每 UTC 日的校准模型请求预算 |
| `replayDailyTokens` | 1,000,000 token | 调用前保守预留，按返回 usage 结算；缺少 usage 或意外中断按预留记账 |

这些预算只管理策略校准，不包含正常压缩、题库提炼或独处的方法回放。手动继续也遵守每日预算。请求计数包括插件可观察到的 DSH 流请求和直接 HTTP 请求（后者的每次重试单独计数）；DSH Provider 内部未上报的重试无法另外计数。请求计数、流水线计数和 token 预算是不同指标；token 估算不是服务商费用账单。一次完整校准可跨越多个批次或多天完成，后台初始化不承诺固定时间内发现改进。保存的预算从下一批生效，不会中断当前请求，也不会使已验证条款失效。提高预算会解除对应预算等待，让后台重新检查；不会清零当天已经发生的用量。

网络故障会保留已成功步骤。若压缩候选被字面量或事实校验明确拒绝，则暂停自动重试，并清除这轮候选检查点；手动继续重新生成，避免每天复用同一份被拒摘要、重复支付核验费用。完整验证、模型开关和策略审核要求均不会因暂停而放宽。

模型现在可以提出新的摘要条款。例如，原文说「只有对外借阅才需要审批」，旧摘要可能只留下「借阅需要审批」。给出普通借阅和对外借阅两个问题，能查出摘要是否把例外写成了通则。条款可以描述任何有证据支持的适用情境、应保留的概念及其关系。

1. 三路回放先确认原文能支撑答案，再让当前配置的压缩流水线实际生成旧策略摘要。检查覆盖全部诊断题。即使最初提供的示例摘要能答对，只要重生成的摘要答错或不能给出依据，也可以提出改进。提案模型会收到用于发现问题的原文、实际生成的摘要、阅读模型的失误类型和回查结果。提案和独立审核的输入均不包含留出题或评分用的答案字段。
2. 模块 A 配置的 DSH 模型可以拟一条通用条款、修订现有自拟条款，或保留现状。程序核验目标、抽象概念字段和内容摘要编号；使用配置的独立审核模型再次核对提案。两次调用都须成功才会测试该新条款。审核使用现有审核模型、地址和环境变量，默认是 Terra。
3. 固定候选后，以相同的源记录、模型配置与篇幅预算分别生成新旧摘要。每个被针对的问题都要改善，对应的独立正例及边界反例都要通过，并且至少一道原先答不好的未见题也要得到改善。随后对目标题、关联的留出题及正对照重新生成摘要再测一遍：旧策略目标题的失败须复现两次，至少一道关联未见题也须两次失败；新策略目标题及关联正例、反例须两次通过。一次偶然改善不允许改写正式指令。已有题目上的正确性和证据引用仍要维持。额度不足、模型拒绝、无充分改进、模型作用范围或样例包在验证期间变化时，保留当前策略。
4. 只有验证通过才切换正式策略版本。在途压缩沿用开始时的快照；下一次压缩使用新版本。设置页展示实际采用的条件、保留概念、关系、回放结果、重复验证计数、采用版本和回滚入口。校准可能调用多次阅读模型、独立审核和完整压缩流水线；**单次校准运行默认最长 30 分钟，`replayTimeoutMs` 可设 10–60 分钟**，独立于 `timeoutMs` 控制的单次压缩流水线时限。分批预算通常会更早暂停新请求，完整验证不必挤在同一次运行内。无依赖的样例和摘要批次最多三路并发，同一题的多跳检索仍串行；并发缩短等待，不减少调用费用，重复验证还会增加调用量。设置页记录实际计数和耗时，不按合成测试耗时承诺真实服务速度。

策略作用范围只包含模型与接口身份、参与内容生成和核验的阶段、摘要和输出预算等影响结果的设置。修改超时、重试、密钥环境变量名、规划频率或其他运行参数不会清空已学条款。改变模型或摘要预算导致范围不匹配时，设置页会在折叠面板外明确显示旧策略版本和变化字段；原条款保留，但暂用基础策略，直到恢复原配置或完成新范围验证。旧版全配置哈希仅在能与当前旧字段精确对应时迁移，否则明确提示需要重新验证。

**手动扩展回放题库。** 在插件数据目录放置可选的 `feedback-cases.json` 即可添加新情境，默认目录为 `~/.dsh/collaborative-compaction/`。可复制随插件提供的证据来源示例。[示例文件](examples/feedback-cases.json)每组包括一个诊断问题 `probe`、一种场景不同但有同类问题的 `positive` 和一个要求不同答案的 `counter`。每个问题写出题目、预期短答、带编号的原记录、需要引用的编号和准确原文；诊断问题另加最初用于回放的摘要。问题和记录编号须全局唯一。每轮最多加载两组手动样例，动态题库另外参与选取。模型判断是否能改好；扩充题库无需修改程序。

只将准备交给已配置模型的回放资料写入该文件。保存在正式策略里的自拟条款最多四条，采用抽象概念字段；程序渲染为统一的摘要指引。发布和回滚都不改模型设置、工具权限或原始历史。回放结论只覆盖验证过的样例。

### 0.3.4 从实际压缩遗漏生成动态题库

「自动提炼脱敏样例」由 `replayHarvestEnabled` 控制，**保留默认开启**，但只在协作压缩总开关、提炼开关和交叉审核 `reviewEnabled` 同时开启时运行。关闭交叉审核会取消正在处理的提炼，并清空待处理原文；重新开启后只处理新任务，不恢复旧任务。设置页保留提炼开关并显示暂停原因。它只观察启用后进入本插件的正式压缩：成功生成的摘要，以及已有候选摘要但未通过事实核验的结果。压缩回放和方法回放不会反过来供给题库。该后台流程不改变本次摘要的提交条件，也不等待题库生成完成才向引擎返回。

此功能会将本次正式压缩的完整原文（最多 120,000 字符）和候选摘要交给模块 A 配置的生成模型，以及配置的独立审核模型。审核接口为 `reviewBase + /responses`，默认是 `https://api.openai.com/v1/responses`；设置页显示当前实际接口及模型，不显示密钥。**这是先向模型发送原文，再提炼脱敏样例；不是先在本机脱敏再发送。** 关闭交叉审核后，自动提炼不会再向这些模型发送原文；已经发出的请求无法撤回，返回结果也不会采用。其他独立开启的规划或核验功能仍按各自配置工作。

1. 使用模块 A 配置的 DSH 模型对照本次冻结原文和候选摘要，寻找实际丢失的关系或约束。候选必须附带可在本次原文中逐字找到的证据。原文组必须能答对，摘要组确实不能答对，才继续提炼；只发现模型调用失败、不完整回答或无法确认的差异时，不建立遗漏样例。
2. 模型保留“为什么会丢信息”的结构，换用另一种虚构情境，生成一道诊断题、一道不同场景的正例和一道边界反例。不能仅把人物改成甲乙后保留原来的路径、数字、私人经历或整段原话。代码筛查敏感字面量和原文重合，独立审核模型再检查脱敏、含义、答案是否有证据，以及是否藏有改变任务的指令。默认使用现有 Terra 审核配置，需与生成模型不同。
3. 只有审核明确通过、合成原文可回答、诊断摘要确实遗漏、正例和边界反例可区分时，才保存到本机 `learned-replay-cases.json`。保存内容是合成的题目与记录、原文和摘要的不可逆摘要指纹、模型标识及时间。`harvest-status.json` 只保存状态和去重指纹。正式聊天的原问题、证据摘录、原摘要和会话编号不写入这些文件。
4. 新入库样例参与后续基线诊断和策略回放。后台先完成现行策略的分批初始化，此后新题库按 24 小时窗口参与对照，其余新题合并等待后续批次。预算暂停、技术失败或仅完成初始化，不得提前把完整策略对照标为完成。题库最多 20 组，满时明确记录，不静默替换已有题目；每轮最多取两组动态样例，优先尚未检查或较久未检查的条目，另可带两组手动样例。内置对照始终保留。提案模型只读取本轮发现集，留出正例和反例在固定候选后才用于对照。只有旧策略到新策略确有改善且重复验证、其余对照均通过时才采用新策略。**样例入库、基线建立和策略生效是不同的结果。**

这条流程会把正式压缩原文临时交给已配置的模型进行核对，模型没有工具执行权限。原文仅保留在当前后台任务内存中；它不是对已有会话目录或旧运行日志的追溯扫描。原来的运行日志没有保存聊天正文，也不会为了补题库把它改成保存全文。程序检查和独立模型审核能减少泄露风险，但不能证明绝对匿名；题库不会自动上传 GitHub。

自动样例来源是本插件正式摘要接口返回候选的路径，内部校准直接调用压缩流水线，不连接收集器。外部隔离测试若使用相同 HTTP 接口，应在已认证请求的 `metadata.dsh_compaction` 设置 `replayLearning: "exclude"`；也可在测试配置关闭 `replayHarvestEnabled`。这项标记只会禁止采样，不能放宽压缩校验。

每日最多开始四次提炼任务，内存队列最多两项；重复来源与摘要不反复加入。**四次指任务次数，不是模型请求数。** 一次完整提炼按流程包含 15–27 次模型请求，提前放弃则更少，底层服务自身重试另计。这是独立于策略校准的额度，不计入上方每日请求 / token 预算。超过单次学习预算（120,000 字符）的来源跳过，绝不截断成局部历史后误判更正。模型服务故障后全队列退避一小时，原任务仅在宿主保持运行且符合当日预算时再试。插件卸载或关闭时取消后台任务，并拒绝旧任务回写。重启不会恢复原文内存队列，之后的新压缩仍可触发收集。模型生成样例可以选择“不确定”或不生成，不能为了填满题库捏造遗漏。

设置页显示当前开关、暂停原因、原文接收模型与接口、队列、今日任务次数、预算范围、最近采用或未采用原因、已入库数量、各组审核模型及时间。每五秒刷新只读状态，不触发模型。「清空动态题库（保留当前策略）」删除动态样例，保留手动样例和已经验证生效的策略；需要撤销策略时使用单独的「恢复上一策略」。自动化测试使用隔离目录、合成来源和模拟模型响应，验证实际宿主接线及拒绝路径；它们不等于正式会话的真实模型效果验收。
