# 0.3.8 隔离回归记录

2026-11-04，Node 22.22.2 / npm 10.9.7，锁定 billion-context v0.1.209。测试只使用临时数据库、虚构文本和模拟模型；不读取正式会话，不发出付费模型请求。

## 提炼权限与生命周期

- `replayHarvestEnabled` 默认仍为 `true`，必须同时满足 `enabled` 和 `reviewEnabled`。
- 真实 HTTP 宿主路径关闭交叉审核后，正常压缩 A 仍工作，自动提炼生成/审核请求为零。
- 关闭审核时清空排队原文并取消在途提炼；立即重新开启，旧审核批准也不能入库。
- 等待队列锁期间取消、正式压缩等待期间改模型或审核接口，都不恢复旧任务。
- 临时回放检索使用同一原文检索实现，但显式禁用全局预处理缓存；搜索与按引用展开都不增加缓存中的原文条目。
- 设置页区分“提炼开关已开”和“因交叉审核关闭而暂停”，显示原文接收接口、模型及独立的任务额度。

## 索引中断恢复

| 场景 | 实际结果 |
| --- | --- |
| 5,000 条首次建库，8 批后强制终止真实 Worker | 2,000 条及游标 1,999 在重新打开后仍保留 |
| 中断期间修改旧消息、删除旧消息、追加新消息 | 恢复只处理剩余 3,001 条与 3 项变更；命中岑舒、青枔、参数及末尾消息 |
| 同一个修订更新 900 条，250 条后终止 | 按 `(revision, seq)` 继续，包含后续删除和追加，共处理余下 652 项 |
| 两个索引实例在批次之间交替更新 | 旧快照不覆盖新修改，最终查询读取完整当前版本 |
| 批次内容全部被过滤 | 已提交的扫描游标仍报告进度，不误判为卡住 |
| 升级已完成的 v2 索引，800 条后追加 1 条 | 复用旧索引，仅索引新增的 1 条 |
| 升级旧的未完成索引 | 保守重放前缀更正和删除，最终完整恢复 |

进度计时测试使用真实 Worker 和缩短的测试专用时限：500 ms 无进展预算下，持续提交的 1.5 s 操作成功；重复进度、错误请求 ID 和旧 Worker 消息不能续期。排队请求不因另一项正常建库超时，关闭可立即取消。

生产时限仍为 120 秒，但现在含义是“当前请求连续没有已提交进度”。长历史可跨越这个总时长；持续卡住仍会失败并保留已提交检查点。未同步完整的索引不会被作为完整搜索结果。
